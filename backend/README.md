# WBTrack Backend

Бэкенд для сервиса, который получает данные из https://pvz.wb.ru/ при помощи клиента pvz-client. Данные сохраняются в базе данных для последующего анализа и ведения статистики.

## Требования

- Docker и Docker Compose
- Доступ к серверу с открытыми портами 80 и 443

## Структура проекта

- `api/` - API эндпоинты
- `core/` - Ядро приложения
- `models/` - Модели данных
- `schemas/` - Pydantic схемы
- `services/` - Сервисы для работы с внешними API
- `tasks/` - Celery задачи
- `nginx/` - Конфигурация Nginx
- `scripts/` - Скрипты для запуска и управления проектом

## Подробная инструкция по установке

### Шаг 1: Подготовка сервера

1. **Подключитесь к серверу по SSH**:
   ```bash
   ssh user@your-server-ip
   ```

2. **Создайте директорию для проекта**:
   ```bash
   mkdir -p /opt/wbtrack
   cd /opt/wbtrack
   ```

3. **Скачайте скрипт установки**:
   ```bash
   curl -o clone_and_deploy.sh https://raw.githubusercontent.com/your-username/your-repo/main/scripts/clone_and_deploy.sh
   chmod +x clone_and_deploy.sh
   ```

### Шаг 2: Запуск установки

1. **Запустите скрипт установки**:
   ```bash
   ./clone_and_deploy.sh
   ```

2. **Что делает скрипт**:
   - Проверяет и устанавливает Git, Docker и Docker Compose, если они отсутствуют
   - Запрашивает URL Git-репозитория (введите URL вашего репозитория)
   - Запрашивает директорию для установки (можно оставить по умолчанию: /opt/wbtrack)
   - Клонирует репозиторий
   - Переходит в директорию backend
   - Создает .env файл на основе .env.example с автоматически сгенерированными паролями
   - Создает учетные данные для доступа к Portainer через Nginx
   - Запускает скрипт deploy_prod.sh

### Шаг 3: Что происходит при запуске deploy_prod.sh

1. **Проверка .env файла**:
   - Скрипт проверяет наличие .env файла

2. **Создание директорий**:
   - Создаются директории для данных PostgreSQL, Redis и Portainer

3. **Генерация SSL-сертификатов**:
   - Если сертификаты отсутствуют, запускается скрипт generate_ssl.sh
   - Создаются самоподписанные SSL-сертификаты для HTTPS

4. **Запуск контейнеров**:
   - Останавливаются существующие контейнеры (если есть)
   - Запускаются новые контейнеры с помощью docker-compose
   - Проверяется статус запущенных контейнеров

5. **Результат**:
   - Выводится информация о доступности сервисов
   - Выводятся команды для SSH-туннелирования

## Доступ к сервисам

### Через веб-интерфейс:
- **Основное приложение**: http://your-server-ip/
- **Portainer**: http://your-server-ip/portainer/ (требуются учетные данные, созданные при установке)

### Через SSH-туннель:
- **PostgreSQL**:
  ```bash
  ssh -L 5433:localhost:5432 user@your-server-ip
  ```
  После этого PostgreSQL будет доступен на вашем компьютере по адресу `localhost:5433`

- **Redis**:
  ```bash
  ssh -L 6380:localhost:6379 user@your-server-ip
  ```
  После этого Redis будет доступен на вашем компьютере по адресу `localhost:6380`

- **Portainer (прямой доступ)**:
  ```bash
  ssh -L 9001:localhost:9000 user@your-server-ip
  ```
  После этого Portainer будет доступен на вашем компьютере по адресу `http://localhost:9001`

- **Приложение (прямой доступ)**:
  ```bash
  ssh -L 8001:localhost:8000 user@your-server-ip
  ```
  После этого API будет доступен на вашем компьютере по адресу `http://localhost:8001`

## Обновление проекта

1. **Подключитесь к серверу**:
   ```bash
   ssh user@your-server-ip
   ```

2. **Перейдите в директорию проекта**:
   ```bash
   cd /opt/wbtrack/backend
   ```

3. **Обновите код из репозитория**:
   ```bash
   git pull
   ```

4. **Перезапустите сервисы**:
   ```bash
   ./scripts/deploy_prod.sh
   ```

## Настройка SSL

Для включения HTTPS:

1. SSL-сертификаты генерируются автоматически при первом запуске

2. Для использования HTTPS раскомментируйте HTTPS секцию в `nginx/conf.d/default.conf`

3. Перезапустите контейнеры:
   ```bash
   docker-compose -f docker-compose.prod.yml restart nginx-proxy
   ```

## Управление через Portainer

1. Откройте Portainer по адресу http://your-server-ip/portainer/
2. Введите учетные данные, созданные при установке
3. При первом запуске Portainer создайте учетную запись администратора
4. Используйте интерфейс Portainer для управления контейнерами

## Безопасность

- Все сервисы, кроме Nginx, закрыты от внешнего доступа
- Доступ к Portainer защищен Basic Authentication
- Сервисы доступны на localhost сервера для SSH-туннелирования
- Для повышения безопасности рекомендуется:
  - Использовать сильные пароли
  - Настроить брандмауэр на сервере
  - Регулярно обновлять образы Docker

## Мониторинг

Для мониторинга состояния контейнеров используйте:
```bash
cd /opt/wbtrack/backend
docker-compose -f docker-compose.prod.yml ps
```

Для просмотра логов:
```bash
cd /opt/wbtrack/backend
docker-compose -f docker-compose.prod.yml logs -f [service_name]
```
